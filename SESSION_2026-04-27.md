## Issues Encountered & Fixes Applied

### 1. `ImportError: libnuma.so.1`
SGLang's `sgl_kernel` requires `libnuma1`.

**Fix:**
```bash
apt-get update && apt-get install -y libnuma1
```

### 2. `FileNotFoundError: ninja`
SGLang's FlashInfer backend JIT-compiles CUDA kernels and needs `ninja-build`.

**Fix:**
```bash
apt-get update && apt-get install -y ninja-build
```

### 3. `hf-xet` not installed
The `hf-xet` package was not installed in this `.venv`, so no uninstall was needed. If it is present in future sessions, remove it:
```bash
uv pip uninstall hf-xet
```

### 4. Bash timeout on first run
The first 7B sweep completed 19/20 configs but the bash tool killed the process at the 1-hour mark during the final `p400_chunk32768` run. The Python script never reached `write_sweep_csv()` or `write_metadata()`, so no CSV or metadata was produced.

**Fix for future:** Use a timeout > 1 hour per model, or run models individually.

### 5. Second run aborted
A second attempt at the full 7B sweep was started but aborted immediately (only printed the header and began config `[1/20]`), producing no useful output.

### 6. `pip` not in `.venv/bin/`
The `.venv` was created with `uv`, so `pip` is not available as a binary. Use `python -m pip` or `uv pip` instead.

## Key Takeaways for Future Agents

- Always check `libnuma1` and `ninja-build` first on a fresh H100 RunPod instance.
- Use `/dev/shm/huggingface_cache` as `HF_HOME` for large models to avoid the RunPod disk quota.
- The `.venv` has no `pip` binary; use `python -m pip` or `uv pip`.
- Each 20-config sweep takes ~45–60 minutes on H100. Plan timeout accordingly.
- If a run is interrupted, existing JSONL files are valid — write a parser to recover the CSV rather than re-running everything.
